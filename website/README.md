# Marketing website

This directory owns the static marketing site, screenshots, social image, and
image-generation tooling. It is separate from the application dashboard build.

`website/` is not a Bun workspace, so `bun install` installs nothing for it and
the Docker build context excludes it. Run these commands from this directory:

```sh
bun run dev      # Local static server on port 4000 (bunx serve@14.2.6)
bun run og       # Regenerate og-image.png using headless Chromium
bun run preview  # Deploy a Vercel preview (bunx vercel@59.25.4)
bun run deploy   # Deploy production (bunx vercel@59.25.4)
```

`serve` and `vercel` are pinned in `package.json` and fetched by `bunx` on
first use. `bun run og` imports `@playwright/test` from the root workspace, so
run `bun install` at the repository root first.

The root `just website`, `just website-og`, `just website-preview`, and
`just website-deploy` recipes forward to these commands.

Install Chromium for image generation with `bunx playwright install chromium`.
To verify generation without replacing the committed image, use
`bun run og /tmp/llmflow-og.png`.

The site uses `screenshot-light.png`, `screenshot-dark.png`, and `og-image.png`.
Additional dashboard screenshots, not used by the page, are kept in `assets/`:
`screenshot-log-light.png`, `screenshot-log-dark.png`,
`screenshot-metrics-light.png`, and `screenshot-metrics-dark.png`. The social
image template and generator live in `scripts/`. Screenshots are currently
maintained assets; they are not regenerated by the application build.
